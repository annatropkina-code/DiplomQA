# План автоматизации тестирования

## 1. Перечень автоматизируемых сценариев

В приложении доступны два способа оплаты: обычная оплата дебетовой картой и выдача кредита по данным карты. 
В эмуляторе банка предопределены две карты: успешная (APPROVED) — 4444 4444 4444 4441, и отклоненная (DECLINED) — 4444 4444 4444 4442. 
Приложение не должно сохранять в своей БД данные карт

**Позитивные сценарии:**

1. Успешная оплата тура дебетовой картой со статусом APPROVED (4444 4444 4444 4441). Проверка появления уведомления об успехе и записи в БД со статусом APPROVED.
2. Успешная выдача кредита по карте со статусом APPROVED (4444 4444 4444 4441). Проверка уведомления и записи в БД со статусом APPROVED.
3. Отказ в оплате дебетовой картой со статусом DECLINED (4444 4444 4444 4442). Проверка появления уведомления об ошибке и записи в БД со статусом DECLINED.
4. Отказ в выдаче кредита по карте со статусом DECLINED (4444 4444 4444 4442). Проверка уведомления и записи в БД со статусом DECLINED.
5. Проверка безопасности: убедиться, что после успешной оплаты в БД не сохраняются данные карты (номер, CVC, срок действия), сохраняется только статус и сумма.

**Негативные сценарии:**

1. Отправка формы с пустыми полями (валидация обязательных полей).
2. Ввод невалидного номера карты (менее 16 цифр, буквы).
3. Ввод невалидного срока действия карты (просроченная карта, неверный формат MM/YY).
4. Ввод невалидного CVC/CVV кода (2 цифры вместо 3).
5. Ввод невалидного имени владельца (цифры, спецсимволы, кириллица).


## 2. Перечень используемых инструментов

* **Java 11** — язык программирования для написания автотестов.
* **Selenide** — фреймворк для UI-тестирования. Обеспечивает стабильные тесты за счет "умных" ожиданий и удобных
  селекторов.
* **Apache DBUtils** — библиотека для работы с БД. Позволяет легко выполнять SQL-запросы для проверки статусов платежей
  в таблицах MySQL и PostgreSQL.
* **JUnit 5** — фреймворк для запуска тестов.
* **Allure** — инструмент для генерации наглядных отчетов (скриншоты, шаги тестов, категории дефектов).
* **Gradle** — система сборки проекта.
* **Docker / Docker Compose** — для развертывания MySQL, PostgreSQL и эмулятора банковских сервисов на виртуальной
  машине (ВМ), так как локально Docker не установлен.

## 3. Перечень и описание возможных рисков при автоматизации

1. **Высокая сложность настройки окружения без локального Docker.** Риск решается через работу на виртуальной машине.
2. **Нестабильная работа эмулятора банковских сервисов.** Возможны таймауты при запросах, что потребует увеличения
   времени ожидания в тестах (timeout).
3. **Большое количество багов в SUT.** Тесты будут часто падать (что является ожидаемым). Потребуется время на ручную
   проверку каждого падения для отделения багов приложения от ошибок в коде тестов.
4. **Различие в структуре БД для MySQL и PostgreSQL.** Запросы к БД могут отличаться, потребуется написание
   универсального DbHelper или двух отдельных.

## 4. Интервальная оценка с учётом рисков (в часах)

* Получение и настройка ВМ, запуск Docker-контейнеров: **4–6 часов**.
* Написание Page Object и хелперов (DbHelper): **6–8 часов**.
* Написание и отладка позитивных/негативных UI-тестов: **15–20 часов**.
* Оформление баг-репортов (Issues): **4–6 часов**.
* Подготовка отчетной документации (Report.md, Summary.md, README.md): **4–5 часов**.
  **Итого:** ~33–45 часов рабочего времени

## 5. План сдачи работ

1. Согласование плана: 1-5 дней с момента отправки.
2. Настройка окружения на ВМ и написание каркаса проекта (Page Objects, хелперы): 3-5 дней.
3. Написание и отладка автотестов (позитивные и негативные сценарии): 7-10 дней.
4. Анализ результатов прогона тестов и фиксация багов в Issues: 2-3 дня
5. Финальный прогон тестов, оформление отчетных документов (Report,Summary): 1-2 день.
